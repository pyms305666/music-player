# 第三轮性能与验证记录（4.1.12）

## 状态

三对独立进程性能对照已完成，原始失败数据与最终数据均保留。唯一连续三批超过 10% 的退步是长歌词夹具稳定堆增加 0.566MiB（15.257%）；用户于 2026-10-05 明确接受这项取舍，保留快速高亮。其余指标继续采用原门槛。正式附件仅在对应提交全部 CI、干净源码打包、签名/散列核验和最终真机回归通过后发布；发布来源以 Release 的 build-info.json 为准。

## 环境与测量方法

- 基线为 4.1.11，源码提交 `9bb36411b0ebe061a4b82cbbbd50d557e68b24cd`；基线生产源码未修改，仅添加同一套测试夹具。
- 桌面：同一 Windows 机器、JDK 25.0.2，使用独立临时数据库、歌曲占位文件与偏好节点；共享逻辑另以 Java 17 验证。
- 安卓：一次性 API 35、x86_64、`sdk_gphone64_x86_64` 模拟器。同一测试 APK 对照两个主 APK；性能夹具拒绝个人手机，实际 Activity 夹具还要求 API 35。
- 安卓最终协议为三对独立进程，版本顺序为旧→新、新→旧、旧→新。每个类别重新启动进程；两个包都重置编译状态并请求 `speed`。实际 debuggable APK 编译状态为 `verify`，不宣称获得 AOT 优化。
- 两侧搜索均在独立方法中预热相同恢复和查询分支；方法返回后清除临时保留引用再采样，避免解释器栈帧保留预热快照。
- GC 请求后确认弱引用哨兵已回收，再请求第二次 GC；保留公开 ART 的 GC 次数、分配/释放字节和原始 total/free/used 堆计数，不从新版内存减去固定差值。
- 安卓峰值为每 10ms 观察到的 Runtime 堆峰值，是采样下界；稳定堆与稳定 PSS 分开记录，不能相互替代。桌面堆使用 MXBean，不等于进程工作集。
- 导入夹具测量 500 首数据库写入，不包含真实音频复制。优化后的批量写入 API 包含首次调用；旧版单条写入仅在夹具建库时做一次 save/remove 初始化。
- 歌词夹具为 1,000 行长文本、500 次高亮更新；时间不包含 500 次实际帧渲染。共享歌词定位另测 100、1,000、10,000 行。
- 曲库恢复夹具测量数据库读取、存在性检查、排序、快照构造及平均过滤耗时。实际界面启动另等待曲库显示就绪；运行时先初始化，安卓对称预热一次 Activity，因此不等于冷进程启动或首帧时间。

## 测量诊断记录

初次安卓顺序执行“导入→歌词→曲库”时，稳定 Runtime 堆出现约 0.47–0.56MiB 固定差额，部分搜索、恢复与 Activity 就绪时间连续三批退步超过 10%。这些结果保留，不能判为门禁通过。旧版歌词夹具约需 160 秒，新版不足一秒，后续进程的运行时历史不同；单独运行曲库并统一编译状态后，固定差额消失，万首查询接近。最终结论仍须来自完整交替协议。

一次导入堆转储的应用对象逻辑统计未显示对应的大对象增长，但不能证明无回归：统计不等于完整 ART 分配账本，且只有一对数据。Android 15 文件 HPROF 转储不保证无条件完整 GC；诊断转储前后分别记录 GC/堆信息，带转储的数据不用于耗时或 PSS 对比。参考：[ART HPROF 实现](https://android.googlesource.com/platform/art/+/refs/tags/android-15.0.0_r1/runtime/hprof/hprof.cc)、[堆计数实现](https://android.googlesource.com/platform/art/+/refs/tags/android-15.0.0_r1/runtime/gc/heap.h)。

独立审查进一步发现预热局部快照可能被长寿命测试栈帧保留；已将预热提取到返回 void 的独立方法。此前测量作为诊断保留，完整三对协议重新执行，不能拼接新旧夹具数据。

## 资源与行为边界

- 下载地址缓存容量 500，成功 4 分钟、失败 45 秒；负结果与未命中区分。定时清理复用来源执行器，关闭后不接收迟到写入。
- 查询缓存复用有界过期缓存组件，保留 50 项/2 分钟及只缓存全部来源正常完成结果的规则。
- 桌面生成文件缓存：封面 256MiB，播放修正 512MiB；只处理直接子目录中的合法生成名普通文件，排除原歌曲、其他名字、子目录、符号链接和临时文件。
- 读写前获取租约；封面展示与媒体播放结束后释放，后台先更新访问时间再解除保护。全部文件在用时可以暂时超出预算，释放后继续清理。维护线程与排队清理 Future 随组件关闭，Future 回调在内部锁外运行。
- 歌词时间轴保存时间及行号，不保留可变元数据；小步正常播放顺序推进，显式拖动与倒退二分查找，重复标签选择最后一个已到达行。
- 安卓歌词字符内容保持稳定，只移动颜色与粗体样式；非时间歌词采用普通文本。预绘制时使用真实布局行位置及内边距定位滚动，不以字符数估算换行。
- 安卓数据库版本 3 新增导入来源映射表；升级保留版本 2 原表。每 50 首写入一个事务，失败回滚该批数据库并清理该批复制的文件；之前成功的批次保留。
- 同批、排队提交及已入库且仍可读的同 URI 去重；删除歌曲会移除映射，可以重新导入。下载及导入共用原子文件名预留，清理仅作用于各自副本。
- 导入进度最多每 200ms 发布，最终状态必发；界面销毁后停止展示并清理未提交副本。取消是协作式：阻塞在 ContentProvider 的打开/读取必须等提供方返回，不承诺立即中断任意提供方。

唯一连续三批超过 10% 的指标是长歌词稳定堆：增加 593,920 B，即 0.566MiB / 15.257%。用户在 2026-10-05 明确选择“接受这项取舍，保留快速高亮方案”。该例外仅覆盖此夹具指标，不修改其他门槛，也不把下降的峰值或 PSS 当作稳定堆没有增加的证据。

补充布局诊断保存在 `lyrics-layout-before-diagnostic.json` 和 `lyrics-layout-after-diagnostic.json`。两侧最终均有 10,000 个实际显示行：旧版为 StaticLayout、新版为 DynamicLayout；完成最终布局后差额仍存在。因此不能将其解释为旧版缺少布局，亦未从新版测量减去任何固定差值。新版可变文本、高亮索引与布局结构带来保留成本；单个夹具不证明长期运行无泄漏。最终测试夹具对称完成布局后才采样稳定内存，并记录布局类型。

## 验证与发布门禁

严格维护性自审和独立 `code-review` / `check-work` 已完成当前源码范围复核，覆盖结构、资源生命周期、并发及跨三轮调用。审查发现并修复排队缓存清理 Future 关闭未完成、锁内回调重入、导入数据库错误分类、显式拖动进度未走二分定位，以及性能夹具的 HPROF 采样边界和预热对象保留问题。没有当前生产源码阻断项；此结论不替代最终性能和发布门禁。

独立复核强制重新执行桌面及共享测试：桌面 42 项，其中 41 项通过、Windows 无创建符号链接权限导致 1 项跳过；共享 Java 17/25 各 93 项均通过。Android 构建/lint 通过，0 错误、26 警告；真实桌面播放、歌词重复标签与前后拖动烟测通过；PowerShell 5.1/7 的原生 UTF-8 JSON 与发布数组夹具通过。一次性 API 35 模拟器的新组件 12 项全部通过。

新增测试覆盖缓存容量/过期/关闭、在用文件保护与淘汰、重复歌词时间标签和跳转、稳定文本与真实换行滚动、导入重复/部分读取失败/事务回滚/关闭/投递拒绝/旧数据库迁移，以及并发文件名预留。Windows 的符号链接跳过不计为通过；新增 Linux CI 运行缓存完整用例，并断言符号链接用例实际执行、没有跳过。
