# ZA音乐双端“幽蓝深空流光感”美术设计与落地规范 (Design Document)

- **日期：** 2026-11-04
- **主题：** 双端（Windows JavaFX + Android 原生）UI/美术重构与动态流光沉浸设计
- **状态：** 待确认 (Pending User Review)

---

## 1. 意图与背景 (Intent & Why)

### 1.1 背景
ZA音乐是一款支持 Windows 桌面（JavaFX）和 Android 手机（原生 Android UI + Media3）的本地及在线音乐播放器。当前两端界面较为偏向早期的硬朗线框与默认灰黑高对比度色块，视觉表现力较单一，层次感和现代流媒体播放器的沉浸呼吸感（如 Apple Music、椒盐音乐、Spotify）存在差距。

### 1.2 目标与意图
用户希望在**不缺失现有丰富信息展示**（包括歌曲时长、音质标识、多源标签、歌词同步、下载管理状态等）的前提下，实现**极简且视觉极其舒适**的双端界面。
经过美术提案与高保真效果图验证，最终选定**“幽蓝深空流光感 (Deep Space Ambient Glow)”**作为核心视觉语言。

---

## 2. 目标、非目标与反面目标 (Goals, Non-Goals & Anti-Goals)

### 2.1 目标 (Goals)
1. **视觉统一与现代审美：**
   - 统一两端的设计语言：深空石墨黑（`#0B0E14` ~ `#131924`）基底、微透浮岛卡片（Frosted Glass）、深浅分明的信息层级、8px ~ 16px 现代化圆角系统。
   - 建立全新的“幽蓝与冰青”主题强调色谱系（主高亮 `#4FA5FF`，辅助渐变 `#2CE6E6`，柔光阴影 `rgba(79, 165, 255, 0.25)`）。
2. **动态流光沉浸感（方案 B 核心）：**
   - **桌面端 (JavaFX)：** 封面区域及背景增加扩散式微光图层。当切换歌曲时，提取封面主导色彩（或在未加载/无封面时使用默认幽蓝渐变），通过柔和的高斯模糊/渐变投影赋予界面呼吸感。
   - **移动端 (Android)：** 播放器主界面及歌词浮岛卡片增加微透磨砂与动态环境柔光投射（Ambient Light Shadow）。
3. **信息完整且优雅：**
   - 保留原有的音质标识、播放模式、进度时间、多源标识，采用紧凑且通透的“胶囊徽章（Capsule Badge）”展示。
   - 歌词展示分明：正在播放行加粗高亮（纯白 `#FFFFFF` + 局部外发光），非焦点行柔和褪光（`rgba(255,255,255,0.45)`）。

### 2.2 非目标 (Non-Goals)
1. 不更换现有 UI 核心技术选型（桌面端继续沿用 JavaFX，不引入庞大第三方组件重写；Android 端沿用现有 XML 布局与 Material 组件，不进行 Jetpack Compose 全盘重构）。
2. 不修改底层的音频解码、Media3 服务、网络多源搜索/下载队列与 SQLite 数据库等任何业务核心逻辑。

### 2.3 反面目标 (Anti-Goals)
1. **切忌纯黑死黑与过饱和荧光：** 绝不采用 OLED 刺眼纯黑（#000000）或过饱和刺眼霓虹色，避免长时间注视产生视觉疲劳。
2. **切忌过度装饰破坏性能：** 绝不在列表中针对每一项加载复杂的实时高斯模糊滤镜导致滚动丢帧；桌面端高斯模糊与阴影仅作用于静态主视口与封面背景，Android 端使用硬件加速的半透明 Drawable 与轻量渐变。
3. **切忌为了“极简”盲目隐藏核心状态：** 严禁精简掉已有的缓冲时间、下载进度指示、歌单排序方式及来源说明。

## 3. 技术约束与平台特性 (Constraints)

1. **Windows 桌面端 (JavaFX 25 / CSS3)：**
   - JavaFX 的 CSS 引擎支持 `-fx-background-color` 的线性与径向渐变（`linear-gradient`, `radial-gradient`）、`dropshadow(gaussian, ...)` 与半透明颜色定义。
   - 封面动态光晕实现：在 `ArtworkPresenter` 中，当封面图像解码完成时，通过异步调色板取样（轻量采样位图四周主要像素的平均 RGB），平滑更新 JavaFX 根节点或封面背底容器的背景径向渐变样式，无需复杂着色器。
2. **Android 移动端 (API 26+ / MaterialComponents / Media3)：**
   - 现有 `activity_main.xml` 采用 `FrameLayout` + `LinearLayout` 结构。
   - 顶部应用栏、列表项、歌词卡片与底部播放面板通过半透明 Shape Drawable（带圆角和 1dp 极细微高光边框）重构。
   - 核心强调色从原有的红橙色（`#F35B3E`）平滑迁移至冰蓝/幽青光谱（`#4FA5FF`）。

## 4. 方案决策与对比 (Approaches Considered)

| 维度 | 方案 A：纯静态样式与资源重绘 | 方案 B：动态流光联动（用户已选定） |
| :--- | :--- | :--- |
| **视觉呈现** | 固定预设幽蓝深空渐变，圆角与发光为静态预设 | 依据正在播放封面动态渲染环境光，具备流光沉浸感 |
| **逻辑侵入性** | 0 逻辑代码变动，仅改动 CSS 和 XML/Drawable | 仅在封面呈现层增加极简颜色提取器，极低侵入性 |
| **体验匹配度** | 80% 符合预览效果 | 100% 达到高保真预览图质感 |
| **性能开销** | 极低 | 极低（轻量采样，不占用主线程，非密集渲染） |

**结论：** 采纳方案 B。

## 5. 详细实现规范 (Detailed Technical Specification)

### 5.1 视觉调色板规范 (Design Tokens)

| Token 名称 | 色值 / 样式 | 适用场景 |
| :--- | :--- | :--- |
| `--app-bg-dark` | `#0B0E14` | 最底主背景基底 |
| `--app-bg-surface` | `#131924` | 侧边栏、卡片容器底色 |
| `--app-bg-elevated`| `rgba(27, 36, 50, 0.75)` | 悬浮卡片、输入框、歌词岛浮层（磨砂质感） |
| `--app-border-light`| `rgba(255, 255, 255, 0.08)` | 1px 容器边缘精细高光线 |
| `--app-accent-primary`| `#4FA5FF` | 主功能按钮、播放键焦点、进度条填充 |
| `--app-accent-glow` | `#2CE6E6` | 流光点缀、焦点高亮渐变尾端 |
| `--app-text-main` | `#F4F7FB` | 歌曲标题、主标签、焦点歌词 |
| `--app-text-sub` | `#8F9CAE` | 歌手名、专辑名、次级信息、非焦点歌词 |
| `--app-badge-flac` | `rgba(44, 230, 230, 0.15)` | FLAC / 无损音质胶囊徽章底色，文本 `#2CE6E6` |

### 5.2 Windows 桌面端实现细节
1. **样式表更新：**
   - 重构 `src/main/resources/styles-desktop.css` 与 `styles.css`：引入上述色彩变量，替换掉旧版的灰色和高反差硬边框。
   - 播放进度条（Slider）升级：细轨槽身，青蓝渐变填充，滑块在 Hover 时微发光扩散。
   - 列表（`ListView` / `TableView`）增加平滑的 Hover 与 Selected 渐变状态，行高由默认约 28px 适度放宽至 36~40px，带来视觉呼吸感。
2. **封面与流光光晕呈现（`ArtworkPresenter.java` 增强）：**
   - 封面背后增加一个平级的 `StackPane` 或带高斯模糊的背景矩形；
   - 异步采样封面平均色后，更新该容器的 `Background`（从封面中心向外扩散的 `RadialGradient`，透明度衰减至 0）。

### 5.3 Android 移动端实现细节
1. **资源更新：**
   - 更新 `android-app/app/src/main/res/values/colors.xml`，将 `accent` 替换为 `#4FA5FF`，新增 `surface_glass` 等半透明颜色。
   - 重绘 `player_panel_background.xml` 与 `field_background.xml`，采用圆角大弧度（16dp）与暗蓝微透质感。
2. **播放与歌词沉浸化：**
   - `artworkView` 升级为圆角矩形，背后挂载带渐变外扩的背景光晕层。
   - 歌词容器升级为“悬浮半透明卡片”，通过微透明度区分焦点行与上下文行。
   - 底部导航栏与播放控制按钮更新为水滴光晕微拟物渐变。

## 6. 构建审查决议与工程实现细节 (Builder Check Resolutions & Calls)

经过系统级架构审查（Builder Check），为确保在不破坏现有非目标（不修改底层解码与数据库、不引发列表滚动丢帧）的前提下实现高保真效果，以下工程决策已由架构师直接敲定并纳入规范：

### 6.1 桌面端 (JavaFX) 动态流光挂载层级
* **承载容器：** 动态流光背景挂载在右侧的 `content` 主视口层（涵盖封面与歌词区），而非最底层的 `app-root`。
* **原因与收益：** 左侧曲库列表（`ListView` / `TableView`）保持深色实底微透表面，确保曲目文字的高对比度阅读体验，并避免大面积重绘引发的滚动丢帧；当用户切换到“纯歌词模式”时，歌词面板无缝承接该视口的扩散流光渐变。

### 6.2 移动端 (Android) 流光渲染与兼容性方案
* **渲染方式：** 采用硬件加速的半透明矢量 `GradientDrawable`（带微光扩散）作为 `artworkView` 的专属光晕层，避免引入高昂的动态多控件模糊开销。
* **磨砂浮岛质感：** 歌词悬浮卡片与底部播放底栏采用 API 26+ 全机型兼容的高质感半透明 Shape（`rgba(27, 36, 50, 0.78)` 配合 1dp 细发光微边框），兼顾零性能负担与现代磨砂视觉质感。

### 6.3 音质胶囊徽章（Badge）取值机制
* **当前播放条：** 依靠现有的 `AudioFileInspector` 进行精确检测，展示高精度音质徽章（如 FLAC、Hi-Res、320K）。
* **在线搜索结果：** 直接读取各来源 API 返回的比特率与格式字段进行徽章渲染。
* **曲库列表行（用户已确认采用自动轻量呈现）：**
  - 基于歌曲文件路径后缀（`.flac`, `.wav`, `.ape`, `.mp3`, `.m4a` 等）进行微秒级内存识别；
  - 无损/高解析度音频（FLAC/WAV/APE）渲染为幽蓝冰青高亮胶囊徽章（`--app-badge-flac`）；
  - 标准音频（MP3/AAC）渲染为低饱和度素雅石板灰胶囊徽章；
  - 既能让用户在浏览列表中对曲目品质一目了然（与桌面端高保真预览图 100% 保持一致），又完全无需扩充 SQLite 数据库或进行额外磁盘 I/O。
