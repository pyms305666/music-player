# 第一轮性能与验证记录（4.1.10）

## 环境和测量范围

- Windows，JDK 25.0.2、JavaFX 25.0.1；共享代码以 Java 17 编译。
- Android：vivo V2528A，Android 16/API 36，正式签名 Release QA 包。
- 曲库过滤使用合成 100、1,000、10,000 首列表，不读取个人桌面数据库。每批 500 次查询，预热后记录三批。
- `LibraryBenchmark` 的 legacy 分支沿用 4.1.9 的 `TrackLibraryService.matches`；indexed 分支使用搜索快照。两者在同一 JVM 参数下分别启动进程。
- 图片使用相同 4000×4000 PNG 文件；目标为桌面 144px、2 倍显示缩放。测量原全尺寸解码与采样解码，另测同图重复显示的缓存命中。
- 堆峰值是 JVM 内存池峰值之和，不能等同于进程工作集；PSS 是 Android `dumpsys meminfo` 的总 PSS。采样噪声与垃圾收集时机影响峰值。

## 本地搜索三批结果

单位：单次查询毫秒（按每批 500 次平均）。

| 曲库 | 原实现批 1/2/3 | 快照批 1/2/3 |
|---|---|---|
| 100 首 | 0.0244 / 0.0255 / 0.0279 | 0.0071 / 0.0048 / 0.0049 |
| 1,000 首 | 0.1358 / 0.1400 / 0.1357 | 0.0231 / 0.0172 / 0.0166 |
| 10,000 首 | 1.5632 / 1.5506 / 1.7666 | 0.2056 / 0.1975 / 0.1720 |

| 曲库 | 原分配量/批 | 新分配量/批 | 原稳定堆 | 新稳定堆 |
|---|---:|---:|---:|---:|
| 100 首 | 24,156,000 B | 540,000 B | 2,537,264 B | 2,563,040 B |
| 1,000 首 | 188,932,800 B | 约 4,966,400 B | 2,801,048 B | 2,992,608 B |
| 10,000 首 | 2,073,995,200 B | 52,521,600 B | 5,451,280 B | 7,365,608 B |

万首稳定堆增加约 1.83MiB，来自保留匹配字段，符合本轮用小索引换取过滤速度的取舍，并非所有内存指标均下降。三批万首峰值分别为原 45,374,440 / 45,400,696 / 45,400,696 B，新 40,086,800 / 45,184,408 / 47,259,024 B，未连续超过原值 10%。索引构建约 6.52ms；该数值不是完整应用启动耗时。

## 封面三批结果

| 指标 | 原解码批 1/2/3 | 采样解码批 1/2/3 |
|---|---|---|
| 首次解码 ms | 60.845 / 42.610 / 40.910 | 148.927 / 82.500 / 84.949 |
| 堆峰值 B | 60,369,144 / 58,087,312 / 59,133,824 | 7,453,168 / 5,786,824 / 5,793,056 |
| 稳定堆 B | 52,539,176 / 52,542,360 / 52,542,360 | 4,738,200 / 5,072,272 / 5,072,376 |
| 同图重复显示 ms | 50.3646 / 45.5310 / 44.6421 | 0.0009 / 0.0005 / 0.0003 |

原图 4000×4000；采样为保持比例的 286×286。按 RGBA 估算，像素占用由 64,000,000 B 降至 327,184 B。单纯给 JavaFX Image 设置小尺寸仍会先分配完整 PNG，本轮改为 ImageIO 读取时采样后交给 JavaFX。大 PNG 冷解码有所变慢，工作位于后台；本轮封面目标为降低峰值和稳定内存，复用缓存降低再次显示成本。该结果不代表网络下载速度或所有图片格式的耗时。

## 真机三批启动与稳定内存

对照旧源码 `c0b8cd0` 的隔离工作区 QA 包和新源码 QA 包，两者使用相同正式签名、版本码 40110，保留个人曲库，均先执行相同的 ART `speed` 编译。设备解锁并在 USB 测试期间保持亮屏。每批强制停止、`am start -W` 冷启动，等待 1.5 秒后取 PSS。

| 指标 | 原实现批 1/2/3 | 新实现批 1/2/3 |
|---|---|---|
| TotalTime ms | 325 / 368 / 301 | 269 / 370 / 289 |
| 稳定 PSS KiB | 99,361 / 99,551 / 99,584 | 99,685 / 99,743 / 100,494 |

启动没有连续三批退步超过 10%，PSS 增加小于 1%。初次对照中锁屏状态的样本已作废，未混入此表。`TotalTime` 表示 Activity 首帧，不能证明万首曲库已完整加载。

## 验证与审查

以下为第一轮源码提交前的记录；最终附件来源、CI 和散列以对应 Release 的 `build-info.json` 为准。

- 桌面 34 项与共享 46 项 JVM 测试通过，共享模块分别在 Java 17/25 验证；新增中文、大小写、文件名、空关键词、元数据快照、快速输入、晚到结果和关闭页面覆盖。
- Android Debug/Release 构建、测试包构建和 lint 通过（0 errors / 27 warnings）；正式 QA 包按 API 28/31/32/33/35/36 验证签名策略。
- 桌面烟测通过：异步恢复、慢 I/O 期间响应、最新选择、最小化末曲循环、暂停恢复、实际输入搜索及播放队列不变。曾因测试硬编码排序和 Windows 偏好隔离不足失败，已改用独立偏好节点和真实搜索控件后通过。
- 真机升级校验检查 UID、曲库/歌词摘要、可读文件、偏好和权限；不清空或写入个人测试曲库。
- 真机已通过 7 项播放、搜索队列和不可变显示行回归，并在播放后再次通过原升级快照校验。独立复核新增的滚动锚点用例已编译，完整 8 项真机复测及最终干净提交安装包的覆盖升级仍是公开发布前门禁。
- 严格代码审查与独立复核结论为 PASS。修复了封面关闭后的尺寸监听器残留、Windows PowerShell 5.1 对 Java 版本标准错误输出的处理；新增关闭后挂载窗口、请求合并、在途尺寸变化与取消后重新请求同一地址的回归均通过。源码审查结论与发布门禁分别记录，未把本地测试通过当作已经发布。

本轮不宣称端到端搜索提速倍数，不做网站可用性保证。在线列表增量刷新、查询缓存和下载调度留到第二轮；歌词、磁盘缓存、大曲库完整启动评估留到第三轮。
