第三轮性能与交互优化：缓存边界、歌词、安卓导入和大曲库测量。

- 下载地址缓存最多 500 项，保留成功 4 分钟、失败 45 秒的有效期，后台清理过期项。
- 桌面封面磁盘缓存预算 256MiB，播放格式修正缓存预算 512MiB；按最近使用时间清理应用生成的文件，在用文件受保护。
- 两端共用歌词时间轴，正常播放顺序推进，拖动进度二分定位；重复时间标签选择最后一个已到达的歌词行。
- 安卓复用歌词全文，只更新高亮样式，按实际换行布局定位滚动位置。
- 安卓导入按 50 首分批事务写入，进度最多每 200ms 更新一次；同一 URI 的重复选择或提交去重，报告成功、重复和失败数量及原因。
- 原子预留私有歌曲文件名，避免同时下载和导入时相互覆盖；复制或事务失败清理未入库副本。
- 修复安卓清空队列后迅速重新播放时，旧通知删除事件可能误停新队列的问题；暂停状态也会撤销旧通知，避免重复通知，保留当前通知的正常停止操作。
- 修复 Windows PowerShell 5.1 发布流程的 UTF-8 标题和 GitHub JSON 数组处理，继续检查附件散列、签名、源码与 CI。

沿用两端布局、播放规则、安装身份、正式 Android 轮换签名和用户数据兼容方案。安卓数据库新增导入映射表，保留旧曲库与歌词。缓存保护在用文件时可能暂时超出磁盘预算；导入取消需要等待正在阻塞的文件提供方返回。

性能数据、测量范围、审查与发布门禁见 `docs/performance-4.1.12.md`。大曲库继续使用内存搜索快照，本轮没有引入全文检索引擎或数据库分页。

隔离模拟器三组对照中，500 首歌曲的数据库写入耗时下降约 93%，1,000 行歌词的 500 次高亮更新耗时下降约 99.5%；测量不包含真实文件复制或逐次帧渲染。长歌词夹具稳定堆增加约 0.566MiB（15.3%），已由维护者明确接受；这项取舍如实保留，其他性能门槛不变。
